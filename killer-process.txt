1. CONCEITOS BÁSICOS
═══════════════════════════════════════════════════════════════════════════════════

O QUE É UM PROCESSO?

Processo = Programa em execução na memória

EXEMPLO:
├─ Firefox aberto = 1 processo
├─ Navegador com 5 abas = ainda 1 processo
├─ VSCode aberto = 1 processo
├─ Python rodando script = 1 processo
└─ Nginx servidor = múltiplos processos

PID (Process ID):
├─ Número único para cada processo
├─ Usado para identificar e controlar
├─ Exemplo: PID 1234
└─ Válido durante execução


CPU vs MEMÓRIA:

CPU (%):
├─ Poder de processamento sendo usado
├─ 100% = usando toda a capacidade
├─ Valores altos = processo pesado
└─ Problema: máquina lenta

MEMÓRIA (RAM):
├─ Espaço em memória RAM sendo usado
├─ Alto uso = RAM limitada
├─ Valores altos = vazamento de memória
└─ Problema: máquina trava


⚠️ IMPORTANTE:

Não mate processos do sistema!
├─ systemd (PID 1)
├─ init
├─ kernel processes
└─ [kthreadd], etc

3. MATAR PROCESSOS COM KILL
═══════════════════════════════════════════════════════════════════════════════════

COMANDO BÁSICO:
───────────────

kill [PID]

Exemplo:
kill 1234

Resultado:
├─ Envia sinal SIGTERM ao processo
├─ Processo recebe aviso
├─ Encerra gracefully
└─ Pode demorar alguns segundos


MATAR IMEDIATAMENTE:
────────────────────

kill -9 [PID]

Exemplo:
kill -9 1234

Resultado:
├─ Envia sinal SIGKILL
├─ Força encerramento imediato
├─ Sem aviso ao processo
└─ Pode perder dados não salvos

⚠️ Use -9 apenas se kill normal não funcionar


MATAR VÁRIOS PROCESSOS:
───────────────────────

kill 1234 5678 9012

Resultado:
├─ Mata 3 processos de uma vez
├─ Ordem: 1234, depois 5678, depois 9012


MATAR POR NOME (killall):
─────────────────────────

killall firefox

Resultado:
├─ Mata todos os processos chamados "firefox"
├─ Não precisa do PID
├─ Cuidado: mata TODOS com esse nome!

Exemplo com -9:
killall -9 firefox


MATAR POR PADRÃO (pkill):
──────────────────────────

pkill -f "python3 script.py"

Resultado:
├─ Mata processos que contêm "python3 script.py"
├─ Mais específico que killall
├─ Usa regex (padrões)

Exemplos:
pkill -f "python"                # Mata todos python
pkill -f "node.*server"          # Mata node server*
pkill -u usuario                 # Mata todos do usuário


═══════════════════════════════════════════════════════════════════════════════════
4. SINAIS DE KILL
═══════════════════════════════════════════════════════════════════════════════════

SINAIS PRINCIPAIS:

kill -1  [PID]    # SIGHUP - Hangup (reiniciar)
kill -2  [PID]    # SIGINT - Interrupt (Ctrl+C)
kill -3  [PID]    # SIGQUIT - Quit
kill -9  [PID]    # SIGKILL - Kill imediato ⚡
kill -15 [PID]    # SIGTERM - Terminate (padrão)
kill -19 [PID]    # SIGSTOP - Pausar processo
kill -18 [PID]    # SIGCONT - Continuar processo
kill -0  [PID]    # Verificar se existe


COMPORTAMENTO:

SIGTERM (padrão):
├─ Processo recebe sinal
├─ Pode ignorar (alguns fazem)
├─ Encerramento graceful
├─ Tem chance de salvar dados
└─ Demora alguns segundos

SIGKILL (-9):
├─ Kernel mata imediatamente
├─ Processo NÃO pode ignorar
├─ Sem graceful shutdown
├─ Perde dados não salvos
├─ Instantâneo
└─ Use só se SIGTERM não funcionar


SEQUÊNCIA RECOMENDADA:

1. kill [PID]           # Tenta normal
2. Espera 5-10 segundos
3. kill -9 [PID]        # Se não funcionou, força

6. MONITORAR PROCESSOS EM TEMPO REAL
═══════════════════════════════════════════════════════════════════════════════════

TOP - INTERATIVO:
─────────────────

top

Dentro do top, comandos úteis:
├─ q = Sair
├─ h = Help
├─ k = Kill process (digita PID)
├─ M = Ordenar por memória
├─ P = Ordenar por CPU
├─ u = Filtrar por usuário
├─ n = Próximo processo
└─ Space = Atualizar agora


MATAR DIRETO DO TOP:

1. Abrir top
2. Pressione k
3. Digite o PID (ex: 1234)
4. Pressione Enter
5. Digite sinal (padrão 15, ou 9 para forçar)
6. Pressione Enter

✅ Processo morto!


HTOP (MELHOR):
──────────────

htop

Características:
├─ Colorido
├─ Mais legível
├─ Barra de scroll
├─ Fácil de entender
├─ Navegação com setas

Dentro do htop, comandos:
├─ ↑↓←→ = Navegar
├─ k = Kill (já mostra processo selecionado)
├─ f = Filter (buscar)
├─ t = Tree (mostra hierarquia)
├─ H = Hide threads
├─ q = Sair
└─ ? = Help


WATCH (repetir comando):
─────────────────────────

watch -n 1 "ps aux | grep firefox"

Resultado:
├─ Atualiza a cada 1 segundo
├─ Monitorar se processo ainda existe
├─ Ctrl+C para sair

watch -n 2 "free -h"            # Ver memória
watch -n 1 "top -bn1 | head -20" # Equivalente a top


═══════════════════════════════════════════════════════════════════════════════════
7. SCRIPTS AUTOMÁTICOS PARA MATAR PROCESSOS
═══════════════════════════════════════════════════════════════════════════════════

SCRIPT: Matar se CPU > 80%
──────────────────────────

cat > kill-heavy-cpu.sh << 'EOF'
#!/bin/bash

# Matar processos que usam mais de 80% CPU

THRESHOLD=80  # 80% CPU

ps aux --sort=-%cpu | tail -n +2 | while read line; do
    CPU=$(echo $line | awk '{print $3}' | cut -d. -f1)
    PID=$(echo $line | awk '{print $2}')
    COMMAND=$(echo $line | awk '{print $11}')
    
    if [ "$CPU" -gt "$THRESHOLD" ]; then
        echo "Matando: $COMMAND (PID: $PID) com $CPU% CPU"
        kill -9 $PID
    fi
done

echo "✅ Processos pesados removidos"
EOF

chmod +x kill-heavy-cpu.sh

Usar:
./kill-heavy-cpu.sh


SCRIPT: Matar se Memória > 50%
───────────────────────────────

cat > kill-heavy-mem.sh << 'EOF'
#!/bin/bash

# Matar processos que usam mais de 50% memória

THRESHOLD=50  # 50% memória

ps aux --sort=-%mem | tail -n +2 | while read line; do
    MEM=$(echo $line | awk '{print $4}' | cut -d. -f1)
    PID=$(echo $line | awk '{print $2}')
    COMMAND=$(echo $line | awk '{print $11}')
    
    if [ "$MEM" -gt "$THRESHOLD" ]; then
        echo "Matando: $COMMAND (PID: $PID) com $MEM% memória"
        kill -9 $PID
    fi
done

echo "✅ Processos com alto uso de memória removidos"
EOF

chmod +x kill-heavy-mem.sh

Usar:
./kill-heavy-mem.sh


SCRIPT: Matar processo por nome
────────────────────────────────

cat > kill-by-name.sh << 'EOF'
#!/bin/bash

# Uso: ./kill-by-name.sh firefox

if [ -z "$1" ]; then
    echo "Uso: ./kill-by-name.sh <nome_processo>"
    exit 1
fi

PROCESS=$1

echo "Procurando: $PROCESS"
ps aux | grep -v grep | grep "$PROCESS"

read -p "Matar? (s/n): " confirm

if [ "$confirm" = "s" ]; then
    killall -9 "$PROCESS"
    echo "✅ $PROCESS morto"
else
    echo "Cancelado"
fi
EOF

chmod +x kill-by-name.sh

Usar:
./kill-by-name.sh firefox
./kill-by-name.sh chrome


SCRIPT: Monitor contínuo
─────────────────────────

cat > monitor-cpu.sh << 'EOF'
#!/bin/bash

# Monitorar continuamente e matar processos pesados

echo "Monitorando CPU e memória... (Ctrl+C para parar)"

while true; do
    echo "=== $(date) ==="
    
    # Top 3 por CPU
    echo "🔴 Top 3 CPU:"
    ps aux --sort=-%cpu | head -4 | tail -3
    
    # Top 3 por memória
    echo -e "\n🟡 Top 3 Memória:"
    ps aux --sort=-%mem | head -4 | tail -3
    
    sleep 5
    clear
done
EOF

chmod +x monitor-cpu.sh

Usar:
./monitor-cpu.sh

8. NICE E RENICE (PRIORIDADE)
═══════════════════════════════════════════════════════════════════════════════════

ENTENDER PRIORIDADE:

Cada processo tem prioridade (-20 a 19):
├─ -20 = Muito alta (não use)
├─ 0 = Normal (padrão)
├─ 19 = Muito baixa (para processos background)
└─ Número menor = prioridade maior


RODAR COM PRIORIDADE BAIXA:

nice -n 10 python3 script-pesado.py

Resultado:
├─ Executa com prioridade 10 (baixa)
├─ Não interfere em outros processos
├─ Usa ciclos livres de CPU


AUMENTAR PRIORIDADE DE PROCESSO EXISTENTE:

sudo renice -n 5 -p 1234

Resultado:
├─ Processo PID 1234 recebe prioridade 5
├─ Fica mais responsivo
├─ Precisa de sudo


VER PRIORIDADE:

ps -o pid,ni,cmd aux | head -10

Resultado:
PID   NI CMD
  1    0 /sbin/init
1234   0 firefox
5678   0 chrome
9012  10 python-script.py (executado com nice -n 10)

9. LIMPEZA E MANUTENÇÃO
═══════════════════════════════════════════════════════════════════════════════════

VER PROCESSOS ZUMBIS:

ps aux | grep defunct

Resultado:
usuario  1234  0.0  0.0     0    0 ?   Z  10:15   0:00 [firefox] <defunct>

⚠️ Zumbis! Pai não coletou o exit status

Matar pai do zumbi:
kill -9 [PID_PAI]


PROCESSOS ÓRFÃOS:

Processo cuja pai morreu:
├─ Adotado pelo init (PID 1)
├─ Será coletado quando morre
├─ Geralmente não é problema


MEMORY LEAK:

Processo cresce em memória:
├─ Usa mais RAM com o tempo
├─ Nunca libera
├─ Típico de bugs

Solução:
├─ Reiniciar o serviço periodicamente
├─ Usar cron job
└─ Buscar atualização


EXEMPLO CRON - REINICIAR SERVIÇO A CADA DIA:

crontab -e

Adicionar:
0 3 * * * systemctl restart nginx        # 3h da manhã
0 2 * * * systemctl restart postgresql   # 2h da manhã

├─ ✅ Flexível (regex)

═══════════════════════════════════════════════════════════════════════════════════
12. SINAIS IMPORTANTES
═══════════════════════════════════════════════════════════════════════════════════

kill -15 (SIGTERM) - Padrão, graceful
├─ Processo recebe notificação
├─ Pode limpar recursos
├─ Pode demorar
├─ Menos destrutivo
└─ Tente primeiro

kill -9 (SIGKILL) - Forçado, brutal
├─ Kernel mata imediatamente
├─ Sem notificação
├─ Sem limpeza
├─ Instantâneo
├─ Pode perder dados
└─ Use só se -15 não funcionar

kill -1 (SIGHUP) - Reiniciar
├─ Recarrega configuração
├─ Mantém processo rodando
├─ Bom para serviços
└─ Exemplo: kill -1 $(pgrep nginx)


SEQUÊNCIA RECOMENDADA:

1. kill [PID]          # Tenta graceful
2. sleep 5             # Aguarda
3. kill -9 [PID]       # Se não morreu, força


═══════════════════════════════════════════════════════════════════════════════════
13. SISTEMA vs USUÁRIO
═══════════════════════════════════════════════════════════════════════════════════

PROCESSOS DO SISTEMA (root):

Nunca mate:
├─ systemd (PID 1)
├─ kernel (kthreadd)
├─ memoria (kswapd)
├─ eventos (kworker)
└─ etc

Identificar:
ps aux | grep root | head

Resultado:
root       1  0.0  0.1  19356  2892 init
root       2  0.0  0.0      0     0 kthreadd
root       3  0.0  0.0      0     0 kworker/0:0

⚠️ [kworker], [kthreadd] = Não mate!


PROCESSOS DE USUÁRIO:

Seguro matar:
├─ Firefox
├─ Chrome
├─ Python script
├─ Node.js
├─ Seus programas
└─ etc


COMO SABER:

ps aux | grep [comando]

Resultado:
root       100  ...  /usr/sbin/nginx         ← Sistema (root)
usuario   1234  ...  firefox                 ← Usuário

Se for root e não conhece, pesquise antes de matar!

14. TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════════════

PROBLEMA: Processo não morre com kill
──────────────────────────────────────

Causa:
├─ Processo em estado D (uninterruptible)
├─ I/O disk travado
├─ Deadlock
└─ Bug do kernel

Solução:
kill -9 [PID]           # Força


PROBLEMA: kill -9 não funciona
───────────────────────────────

Causa:
├─ Processo zumbi
├─ Pai não coletou
├─ PID já morreu
└─ Erro no comando

Verificar:
ps aux | grep [PID]

Se mostra <defunct>, matar pai:
kill -9 [PID_PAI]


PROBLEMA: Máquina lenta, não sei qual processo
────────────────────────────────────────────────

Solução:
ps aux --sort=-%cpu | head -10     # Ver topo CPU
ps aux --sort=-%mem | head -10     # Ver topo memória

Depois:
kill -9 [PID_DO_PESADO]


PROBLEMA: Preciso saber o que o processo faz antes de matar
─────────────────────────────────────────────────────────────

ps aux | grep [PID]                # Ver comando completo
ps -efl | grep [PID]               # Ver detalhes
lsof -p [PID]                      # Ver arquivos abertos
/proc/[PID]/cwd                    # Ver diretório de trabalho
cat /proc/[PID]/cmdline            # Ver comando exato


PROCESSO NÃO APARECE EM NENHUM LUGAR:
──────────────────────────────────────

Causas:
├─ Já morreu
├─ PID errado
├─ Processo de outro usuário

Verificar:
ps aux | grep [NOME]               # Procurar por nome

Se não encontrar:
ps aux                             # Ver tudo

Se mesmo assim não aparecer:
sudo ps aux                        # Ver como root

EXEMPLO 5: Rotina de limpeza automática
─────────────────────────────────────────

Matar processos Firefox com > 1 hora de CPU:

cat > daily-cleanup.sh << 'EOF'
#!/bin/bash

# Rodar: crontab -e
# Adicionar: 0 * * * * /home/usuario/daily-cleanup.sh

THRESHOLD=3600  # 1 hora em segundos

ps aux | grep firefox | grep -v grep | while read line; do
    TIME=$(echo $line | awk '{print $10}')
    SECONDS=$(echo $TIME | awk -F: '{print $1*3600 + $2*60 + $3}')
    PID=$(echo $line | awk '{print $2}')
    
    if [ "$SECONDS" -gt "$THRESHOLD" ]; then
        echo "Matando Firefox PID $PID (tempo: $TIME)"
        kill -9 $PID
    fi
done
EOF

chmod +x daily-cleanup.sh

16. RESUMO FINAL - FLUXO RÁPIDO
═══════════════════════════════════════════════════════════════════════════════════

MÁQUINA LENTA?

1. VERIFICAR:
   ps aux --sort=-%cpu | head -6       # Ver topo CPU
   ps aux --sort=-%mem | head -6       # Ver topo memória
   htop                                # Ou melhor ainda

2. IDENTIFICAR culpado:
   ├─ Firefox comendo 80% CPU?
   ├─ Chrome comendo 70% memória?
   ├─ Python script runaway?
   └─ Nginx trabalhando demais?

3. MATAR:
   kill -9 [PID]                       # Imediato
   ou
   killall -9 [NOME]                   # Por nome

4. VERIFICAR:
   ps aux | grep [processo]            # Confirmar que morreu

5. INVESTIGAR (depois):
   └─ Por que ficar pesado?
      └─ Bug no código?
      └─ Configuração errada?
      └─ Não era pra rodar?


PROCESSO SEGURO PARA MATAR?

SIM se for:
├─ Firefox
├─ Chrome/Chromium
├─ Seu Python script
├─ Seu Node.js
├─ Seu Java
└─ Seus programas

NÃO se for:
├─ systemd
├─ kernel
├─ init
├─ [kworker]
├─ nginx (a menos que sabe por quê)
├─ postgres (a menos que sabe por quê)
└─ Processos do sistema


PROCESSO NÃO RESPONDE?

kill [PID]           # Tenta graceful
sleep 5
kill -9 [PID]        # Se não funcionou, força


AUTOMATIZAR?

cat > kill-script.sh << 'EOF'
#!/bin/bash
ps aux --sort=-%cpu | grep [NOME] | awk '{print $2}' | xargs kill -9
EOF

chmod +x kill-script.sh

🎯 DICAS DE OURO

1. Prefira "kill [PID]" a "kill -9 [PID]"
   - Graceful é melhor
   - Só força se necessário

2. Use "ps aux --sort=-%cpu" para encontrar pesados
   - Mais rápido que top
   - Fácil copiar PID

3. Estude antes de matar
   - Pesquise o nome do processo
   - Não mate se é sistema

4. Monitore regularmente
   - top / htop
   - Veja tendências
   - Identifique memory leaks

5. Automatize
   - Scripts para limpeza
   - Cron jobs
   - Alertas
